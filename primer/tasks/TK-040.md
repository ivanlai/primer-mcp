## What to do
**What's gone wrong:** Write-path cascades (TK-033) only fire when writes go through the tools. Edits made while the server is not running — hand-edits, or another session writing files directly — leave parent status stale with nothing to ever catch it. This is the failure mode that actually occurred in this repo: ST-016 and ST-019 sat marked "todo" with all children verified, and were only noticed and fixed by hand (commits 483663d, fc77dbd).

Fix at read time, with LLM rectification rather than silent auto-repair: `list_actionable` already loads every ticket and `derive_status` already exists, so compare derived vs stored for each story/epic while building the output. Where they disagree, emit a nudge line naming the ticket and the remedy — e.g. "ST-016: all children verified but story is marked todo — update_ticket to fix" — and let the agent decide. The stored file is not modified by the scan; a read-only tool must stay read-only.

## Testable Outcome
A store where a story's stored status disagrees with its derived status (e.g. all children verified but story still todo) produces a nudge line in list_actionable naming the ticket and the fix; a consistent store produces no such line.
