## Parent Epic
[[EP-001]]

## What
An explicit tool for when a verified task's fix did not hold. Deliberately not a generic update_ticket status edit — the query and graph tools story rejects status changes on terminal tickets so that reopening is always an intentional, recorded act. Prior verified_evidence is preserved in the body rather than deleted, since it was true when written.

## Acceptance Criteria
- [ ] Reopening the last verified task of a done story reverts both story and epic
- [ ] A ticket blocked_by the reopened task is no longer offered by get_next_action
- [ ] Reopening a non-verified task fails with an actionable error naming the current status

## Definition of Done
- [ ] No cascade to dependents needed — readiness is computed per call
- [ ] Open question resolved: whether spikes should be reopenable too
