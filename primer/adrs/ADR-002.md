## Parent Epic
[[EP-001]]

## Context
A story is done when all its tasks are verified and its spikes done; an epic is done when all its stories are. Nothing sets this today, so a story whose tasks are all verified still reads `status: todo` on disk — a visible lie in a store whose selling point is being browsable on GitHub.

## Decision
Write tools cascade derived status into parent files. verify_task and complete_spike may complete a parent; create_task, create_spike and create_story add unfinished children and so may un-complete one, reverting `done` to `in-progress`. Done requires at least one child, so a childless story is never vacuously done. Derived `done` overwrites `blocked` — there is nothing left to proceed with.

## Alternatives Considered
- Compute derived status at query time only — rejected: leaves every story file stale on disk, and would force all three read tools to carry derivation logic
- Cascade upward only, never reverting — rejected: reopening work would leave a story marked done above an unstarted task

## Consequences
Read tools become trivial: they report stored status and are always correct. Cost: reopening finished work touches its ancestors, so create_task under a done story writes three files instead of one. The cascade is only sound because update_ticket refuses status changes on terminal tickets — see the `verified` ADR.
