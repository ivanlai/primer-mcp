## What to do
**What's gone wrong:** `</script>` is unescaped in export_graph (export.py:378) — ticket data is embedded into an inline script block via `json.dumps`, which leaves that literal verbatim. A ticket body that quotes HTML or code (e.g. discussing the export feature itself, or pasted test HTML) terminates the script element early: graph.html renders broken, and everything after the marker is parsed as author-controlled HTML — an injection vector as well as a rendering bug.

Fix is one line: `json.dumps(...).replace("</", "<\\/")`.

## Testable Outcome
A ticket whose body contains a literal script-closing tag exports to a graph.html that still parses and renders; the sequence appears escaped in the embedded JSON.
