The tools never write it — it comes from a hand edit. ### Details
The bug: tasks finish via completed -> verified and have no `done`. A task file carrying `status: done` failed schema validation on load, and because every tool loads the whole store, one bad line stopped everything until the file was fixed by hand. The tools never write `done` on a task; it arrives from a hand edit (or an agent calling update_ticket with a status meant for stories).

First attempt, rejected: refuse `done` in update_ticket with a pointer to complete_task/verify_task, plus re-validate every ticket in dumps_ticket before writing. It worked, but it was enforcement in a tool whose stance is guidance over enforcement (ADR-008), and it did nothing for the hand-edit case, where the file is already on disk. A clearer error message was also considered and rejected for the same reason: it still blocks.

Chosen: accept `done` on read and treat it as `completed`. `completed` is the safe reading because it still requires verification; reading it as `verified` would skip the evidence step. The agent is prompted to confirm with the user through the existing "completed but not verified" surface, so with no answer the task simply waits for verify_task. This also removes the original corruption path: however `done` gets there, the store keeps loading.

Removed test_models.py::test_task_rejects_done, which encoded the old stricter rule; the new TestHandEditedTaskDone tests cover the replacement behaviour.
