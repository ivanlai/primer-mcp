## Parent Story
[[ST-020]]

## What to do
Found while dogfooding in primer-mcp-eval (0.1.5): epics, ADRs and stories with two or more goals, alternatives, criteria or ADR links are written with 8-space indentation from the second section onward, which Markdown and Obsidian render as code blocks. Tickets whose values are all single lines are fine. Cause: the templates in `templates.py` call `dedent` on an f-string after interpolation, so a multi-line value's unindented lines leave no common indentation to remove. Fix the templates so bodies are flush-left whatever the field values, and add tests with multi-line values for each ticket type.

## Testable Outcome

## Completion Notes
Restored pre-248cb66 templates (explicit f-string lines, no dedent); test covers multi-line values for all five types

- Cause: commit 248cb66 rewrote every template as `dedent(f"""...""")`. dedent runs after interpolation, so a multi-line value's unindented lines left no common prefix to strip, and bodies kept 8-space indentation.
- Only 0.1.5 was affected; 248cb66 landed after the 0.1.4 tag.
- Fix: restored templates.py to its pre-248cb66 form, which builds each body from explicit f-string lines and never touches indentation.
- A test parametrised over all five templates uses multi-item lists and newline-containing text and asserts no line starts with whitespace; it failed on all five before the fix.

### Details
The existing template tests only used single-item lists, which is why the regression shipped: with single-line values every line keeps the same indentation and dedent works. Considered keeping the triple-quoted style by dedenting the template first and filling it with str.format; rejected because the restored version is already proven, is no longer, and has no brace-escaping pitfalls. The server.py prompts use the same dedent(f"""...""") pattern but only interpolate single-line values (scope sentence, project name), so they render correctly and were left alone. This repo's own ticket store had no affected tickets; primer-mcp-eval's epics, ADRs and stories created with 0.1.5 need their bodies fixed there.
