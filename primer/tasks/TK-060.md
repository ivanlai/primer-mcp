## Parent Story
[[ST-020]]

## What to do
A ticket with broken YAML surfaces as a raw ScannerError with no file name, so the agent can't tell which ticket to fix. Give it the same agent-steering treatment schema errors already get: which file, where, and the next step.

## Testable Outcome
A tool call against a store with one malformed-YAML ticket returns a message naming that file, the line, and both remedies (fix the syntax, or git checkout as a fallback); existing schema-error behaviour unchanged.

## Dependencies
- (none)

## Completion Notes
`load_tickets` now catches `yaml.YAMLError` alongside pydantic's `ValidationError`. A ticket with broken YAML (e.g. a stray colon in a hand-edited list) used to reach the agent as a bare `ScannerError` with a line number but no file name, via `_call`'s catch-all. It now gets a `GateError` naming the file, the line and column as an editor shows them, the parser's problem, and two remedies: fix the syntax, or `git checkout` the file as a fallback that discards uncommitted edits. New test in `test_graph.py`, confirmed to fail without the fix.

### Details
Found while preparing to explain ADR-007's "know the limit" point: its consequences say `git checkout` "is what the load error already advises", but that was only true for schema errors. YAML errors are raised by the frontmatter parser before pydantic runs, so they never reached the helpful handler.

Fixing the syntax is offered first because `git checkout` throws away every uncommitted change to the file, not just the broken line. The server does not attempt a repair itself: it cannot know what a malformed line was meant to say, and the store belongs to the user (ADR-007). The model reads the message and decides, usually fixing the line with its own editing tools.

The parser's line mark counts from the top of the file, so `line + 1` matches what an editor shows (checked against real files). Scope is `load_tickets` only, which nearly every tool goes through; single-ticket reads in `tickets.py` and `backlog_ops.py` that parse one file directly still surface the raw error for that file.
