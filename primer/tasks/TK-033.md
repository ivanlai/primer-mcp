## What to do
**What's gone wrong:**
1. Reopening a task never re-derives parent status (tickets.py:365) — `recompute_parents` is only wired into `create_*`, `verify_task`, and `complete_spike`. `start_task`, `complete_task`, and `update_ticket` never call it. So if you reopen a task under a done story, the story stays "done" and `list_actionable` reports "Every epic is done. Nothing is outstanding." while work is actually in progress.
2. `delete_ticket` doesn't recompute either (store.py:226) — a story has one verified task and one todo task; the user abandons the todo task with `delete_ticket`. Every remaining child is terminal but the story stays "in-progress" forever — nothing ever re-derives it until an unrelated create/verify under that story happens to run the cascade.

Fix: call `recompute_parents` from every write path that changes a ticket's status or removes a ticket. `delete_ticket` lives in store.py; note `recompute_parents` reloads the store, so call it after the file is gone.

## Testable Outcome
Reopening a task under a done story reverts the story (and epic) to in-progress; deleting the last unfinished child of a story marks it done. Both covered by tests that fail on the current code.
