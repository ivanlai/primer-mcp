## Parent Epic
[[EP-001]]

## Context
The schema carried both `blocks` and `blocked_by` on every ticket. They are the same directed edge stated from opposite ends, so the two can disagree, and update_ticket would have to either write both files to keep them in sync or let them drift.

## Decision
Remove `blocks` from the schema. `blocked_by` is the only stored edge field, and the graph is built from it alone. The reverse direction — what does this ticket hold up — is a graph successor lookup rendered by get_ticket at read time, not a stored field.

## Alternatives Considered
- Keep both fields and mirror-write both ends on every update — rejected: multi-file writes for what is one fact, and needless complexity
- Keep both fields and union them at load time without mirroring — rejected: files look asymmetric when read by hand and the second field earns nothing
- Keep `blocks` as the survivor instead — rejected: the natural authoring order has the newer ticket declaring what holds it up, so blocked_by always references an already-existing ticket

## Consequences
One fact, one place, no drift possible. Cost: recording that one ticket blocks five others is five edits to five files rather than one. Safe to remove now because the ticket store was still empty; `extra=forbid` means a stray `blocks:` key now fails validation with a clear error.
