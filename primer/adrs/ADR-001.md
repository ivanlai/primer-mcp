## Parent Epic
[[EP-001]]

## Context
get_next_action must return one unambiguous instruction. Several gates can be unmet simultaneously — a task may sit at `completed` awaiting verification while a different story has no tasks at all — so the gates need a total order. With more than one epic open, the tool also has to decide whether to range across all of them.

## Decision
Task-state gates outrank creation gates: a task at `completed` or `in-progress` is surfaced before any 'create the next thing' gate. Scope every check to the oldest epic that is not done; other epics are invisible until it closes. Within that epic there is no story-level scoping — the oldest ready task wins regardless of which story owns it. Ready work is offered before planning the next story's tasks.

## Alternatives Considered
- Structural gates first, following the numbered list in architecture.md literally — rejected: it tells the agent to create a new story while a completed task sits unverified, which is the exact dangling state the two-phase gate exists to prevent
- Project-wide scan across all epics — rejected: bounces the agent between epics turn to turn; the author designed for one epic at a time
- Story-at-a-time scoping mirroring the epic rule — rejected: blocked_by already sequences work that must be ordered, and a second implicit gate can strand a ready task behind an unrelated stuck story
- Planning the next story before working ready tasks — rejected during dogfooding: with eight migrated stories, seven task-less, it would keep recommending task planning while a ready task sat untouched

## Consequences
The ladder is deterministic and testable rung by rung. Cost: with multiple epics open, work in the newer one is unreachable until the older closes, which is intended but will surprise anyone expecting a global view. The ready-work-before-planning ordering was found by migrating this project's own backlog before writing any code.
