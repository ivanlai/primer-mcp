## Parent Epic
[[EP-001]]

## What
Make a field change a non-event. Unknown frontmatter keys are preserved rather than rejected, so removing or adding a field never bricks an existing store, and record a schema version so a store's vintage stays knowable — the one part that cannot be added retroactively.

## Acceptance Criteria
- init_project records the schema version in config.yaml
- A store from any version stays readable; unknown fields are preserved, not dropped
- An invalid ticket no longer tells the user to hand-edit or delete it

## Definition of Done
- The stamp is recorded, never enforced. Tolerating unknown fields removes the need for migration, so no engine and no version gate
