## What
A high-effort pre-ship code review (2026-08-12) of `src/primer_mcp/` confirmed ten findings. Seven are fixable now and are broken down into the child tasks below; each task body carries the file/line and a concrete failure scenario so any session or model can pick it up without the review context.

The dominant theme is **derived-status cascade misses**: `recompute_parents` is only wired into the create tools, `verify_task`, and `complete_spike`, so several write paths can leave a parent story/epic with a stale status. This same class of miss already happened twice in this repo's own history (ST-016 and ST-019 had to be marked done by hand).

## Deferred (post-v0, recorded so it is not lost)
The review also confirmed a redundant-I/O finding, parked per the "improvements wait until after v0" rule and benchmarks showing it harmless at current scale (list_actionable: 6.7 ms live store, 43 ms at 550 tickets):

- `export.py:357` — export_graph re-reads and re-parses every ticket file (find_path + read_text + loads_ticket per ticket) immediately after load_tickets already read and validated the whole store; each find_path also re-runs require_store. The same double-read pattern exists in get_ticket (store.py:49+53) and update_ticket (store.py:183-184). Cheapest fix: have load_tickets (or a sibling) return bodies alongside tickets.
