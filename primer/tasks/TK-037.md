## What to do
**What's gone wrong:** `_call` only catches `GateError` (server.py:40) — but tickets are advertised as hand-editable ("Hand-edit where the tools fall short"), and hand-edited files can raise other exceptions that reach the agent as raw tracebacks instead of the steering messages the errors.py contract promises:

- `complete_task` on a task whose body lost its `## Completion Notes` heading raises a bare `ValueError` from `_update_section` (tickets.py:62).
- `update_ticket` / `start_task` / `delete_ticket` on a schema-invalid file raise raw pydantic `ValidationError` from their direct `loads_ticket` calls — `load_tickets` wraps this in `GateError` for whole-store reads, but the single-file call sites do not.

Fix at whichever level is cleanest: wrap the single-file `loads_ticket` call sites the way `load_tickets` already does, and/or broaden `_call` to translate unexpected exceptions into a steering message naming the file and the remedy. Keep the errors.py contract: every error tells the agent what to do next.

## Testable Outcome
complete_task on a task whose body lacks its target section, and any single-ticket tool on a schema-invalid file, return a steering message naming the file and the remedy — not a traceback.

## Completion Notes
Added a broad `except Exception` to `_call` in server.py that formats unexpected errors as `TypeName: message` instead of letting tracebacks propagate. Covers missing sections (`ValueError`), invalid frontmatter (`ValidationError`), and any other failure from hand-edited tickets. One test added to `test_server.py` confirming the behaviour.
