## What to do
Found while dogfooding in primer-mcp-eval (0.1.6). Three problems, all in how the frontmatter and body are kept in step:

1. **`body_sections` leaves the frontmatter stale.** `update_ticket(ticket_id="TK-007", body_sections={"Testable Outcome": "..."})` rewrote the body section but left the old `testable_outcome` in the frontmatter, so the ticket contradicted itself (primer-mcp-eval TK-007, before its manual fix).
2. **`blocked_by` leaves the body stale.** `update_ticket(blocked_by=[...])` updates the frontmatter, but the body's `## Dependencies` still says `- (none)` (primer-mcp-eval TK-002 and TK-007).
3. **The blank line before the next heading is lost.** `_update_section` (`tickets.py:60`) joins new content straight onto the next `\n## ` heading. It is shared by `update_ticket` (`store.py:148`), `complete_task` (`tickets.py:424`), `verify_task` (`:472`) and `complete_spike` (`:510`), so all four drop the blank line (for example, completion notes run straight into `## Verification Evidence`).

Which fields should match. These mirrored pairs should say the same thing: task `testable_outcome` / Testable Outcome; story `acceptance_criteria` / Acceptance Criteria and `definition_of_done` / Definition of Done; epic `goals`, `constraints`, `non_goals`, `success_criteria`; ADR `context`, `decision`, `alternatives` / Alternatives Considered, `consequences`; `blocked_by` / Dependencies. **Not** completion notes: by design, `completed_notes` is a one-liner and `## Completion Notes` holds the fuller summary (`server.py:217`, CLAUDE.md section), so they must not be forced equal. The same goes for `verified_evidence` if the body is later expanded.

Recommended approach (confirm with Ivan before building; ADR-008, guidance over enforcement): sync single-line fields automatically, and render `blocked_by` into Dependencies. For list fields, where parsing bullets back out of prose is fragile, update the body and return a warning that the frontmatter list was not changed, rather than guessing or refusing.

## Completion Notes
Mirrored body sections and frontmatter fields now update together; section updates keep a blank line before the next heading

- Editing a mirrored section through update_ticket (Testable Outcome, Acceptance Criteria, the epic lists, the ADR sections, spike Question/Timebox) updates its frontmatter field in the same write. Lists are read back from '- item' bullets; if a list section holds prose, the body is updated and a note says the frontmatter was left alone.
- blocked_by now renders '- [[ID]]' bullets into Dependencies (via update_ticket and sweep_blocked_by); editing Dependencies as bullets sets blocked_by and goes through the same existence and cycle checks.
- Completion notes, evidence and findings are deliberately not mirrored: the frontmatter holds the one-liner, the body the full account.
- _update_section keeps one blank line before the next heading, fixing update_ticket, complete_task, verify_task and complete_spike at once.

### Details
The sync design was chosen with Ivan from three options: sync everything and warn when a list can't be read; sync single-line fields only and always warn for lists; or warn only. Warn-only and lists-warn-only were rejected because no tool can set frontmatter list fields, so both push the fix onto hand-editing YAML, and list_actionable reads three of these fields (task testable_outcome, story acceptance_criteria[0], epic goals). The primer-mcp nudge on story completion asks agents to revise acceptance criteria, so list edits are the common case, not the edge case. Reading bullets back is reliable because the templates write lists in exactly that form; prose is never guessed at, in line with ADR-008 (guidance over enforcement).

body_sections is now applied before status and blocked_by, so a Dependencies edit can feed blocked_by and an explicit blocked_by still produces the final Dependencies rendering. Dependencies use wikilinks, matching the Parent and Governing ADRs sections, so Obsidian's graph shows the edges. Epics, ADRs and spikes have no Dependencies section and are left unchanged.

Removing the duplication altogether (mirrored text only in the body) was rejected as a schema and list_actionable change far too big for a bug fix. Existing tickets whose bodies lost the blank line are not rewritten; they pick up the spacing the next time a section is updated.
