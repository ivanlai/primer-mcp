## Parent Story
[[ST-020]]

## What to do
`primer-mcp --version` and the MCP server handshake both report a hardcoded 0.1.0 while the published package is 0.1.4. Read the version from the installed package metadata so pyproject.toml is the single place a release bumps it.

## Testable Outcome
primer-mcp --version and the MCP server both report the version from pyproject.toml

## Dependencies
- (none)

## Completion Notes
Version read from installed package metadata; server handshake and --version now match pyproject.toml

- `__version__` now comes from `importlib.metadata.version("primer-mcp")` instead of a hardcoded "0.1.0".
- The MCP server reuses it, so the handshake version and `primer-mcp --version` agree.
- A test compares the version a client receives in the handshake with pyproject.toml; it fails if a hardcoded version comes back.
- Releases now bump only pyproject.toml (plus server.json for the registry).

258 passed, mypy + ruff clean, primer-mcp --version prints 0.1.4 (commit 6277837)
